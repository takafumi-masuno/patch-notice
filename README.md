# Patch Notice

情シスの周知に使える、脆弱性とアップデートの情報サイトです。6時間ごとに公式の情報源から更新します。

## 画面

| URL | 内容 |
|---|---|
| `/` | 直近7日の要対応と要確認、絞り込み付きの全件一覧 |
| `/items/[id]/` | 悪用の状況、要約、情シスの対応、社員向けの周知文、出典 |
| `/certificates/` | 証明書の期限、認証局の事案 |
| `/sources/` | 情報源と帰属表示、自動で取得していない製品の公式リンク |
| `/feed.xml` | 全件の RSS（新しい順に50件） |
| `/feed-action.xml` | 要対応の RSS（新しい順に50件） |

```sh
pnpm run pipeline  # data/ を作る
pnpm dev           # http://localhost:3000/patch-notice/
```

ビルド時に `data/` を読みます。`data/` がなければ、全ページを準備中の表示にします。別の場所を読むときは `PATCH_NOTICE_DATA_DIR` を指定します。公開用のビルドでは `PATCH_NOTICE_REQUIRE_DATA=1` を指定し、データがなければビルドを失敗させます。

## テスト

```sh
pnpm test                               # ユニットテスト
pnpm exec playwright install chromium   # 初回のみ
pnpm e2e:build                          # E2E 用にデータあり、データなしの2種類を書き出す
pnpm e2e                                # 画面とアクセシビリティのテスト
```

E2E のデータは `e2e/fixtures/` の自作データです。実際の記事は使いません。

## 証明書の期限

`src/content/certificates.json` に手で登録します。公式情報を見て日付を確認し、`sourceUrl` と確認日の `checkedAt` を入れます。形式の誤りや `https` でないリンクは、ビルドで止まります。

## データ取得

```sh
pnpm run pipeline
```

公式の情報源から取得し、`data/` に JSON を保存します。`data/` は main の管理対象外で、公開用のデータは `data` ブランチに保存します。

| ファイル | 内容 |
|---|---|
| `items.json` | 公開用の項目（直近90日分）。本文は含みません |
| `status.json` | 情報源ごとの取得結果 |
| `state.json` | 次回の差分取得に使う値と KEV の CVE 一覧 |
| `summaries.json` | AI 要約の保存先。本文は含みません |

緊急度は `src/pipeline/classify.ts` の規則で判定します。AI には判定させません。

## 定期更新

`.github/workflows/update.yml` が6時間ごとに次の順で動きます。

1. `data` ブランチを `data/` に取り出す
2. `pnpm run pipeline` と同じ処理で取得と要約を行う
3. `data` ブランチへコミットする
4. `publish.yml` でビルドして公開する

| 取得の終了コード | 意味 | 動作 |
|---|---|---|
| 0 | 成功 | 保存して公開する |
| 2 | データは保存済みだが確認が必要（AI の設定の問題、通信する全情報源の失敗） | 保存して公開し、最後に実行を失敗にする |
| それ以外 | 異常終了 | 保存も公開もしない |

`ANTHROPIC_API_KEY` は GitHub の Secrets に登録します。未登録のときも保存と公開は行い、最後に実行を失敗にします。

### 更新が止まったとき

閲覧時に取得時刻が24時間より前なら、全ページに警告を出します。通信する情報源がすべて失敗した回は、取得時刻を進めません。GitHub の通知は、ワークフローの cron を最後に編集した人に届きます。公開リポジトリの定期実行は60日間活動がないと止まるので、その場合は次のコマンドで再開します。

```sh
gh workflow enable update.yml
```

## 情報源の追加

利用条件を確認してから追加します。ポートフォリオの主な目的が転職と案件獲得なので、非商用に限る情報源や自動取得を禁じる情報源は使いません。Cisco、Microsoft（MSRC）、Apple、Python ブログはこの理由で取得していません。`data` ブランチは公開されるので、一度載せた内容は履歴に残ります。

追加するときは `src/lib/credits.ts` にも帰属表示を載せます。載せないとテストが失敗します。

## AI 要約

CISA KEV の項目を、Claude Sonnet 5.5 で日本語に要約します。`.env` に `ANTHROPIC_API_KEY` を入れると有効になり、なければ要約せずに処理を続けます。

- **AI が書くのは事実の要約だけです。** 悪用の状況、情シスの対応、社員向けの周知文は、コードの判定と定型文（`src/lib/notice.ts`）で作ります。
- **要約は `src/pipeline/summary/check.ts` で検証します。** CVE、バージョン、英単語が元データと一致しない要約、助言や悪用の断定を含む要約は公開しません。
- **失敗しても公開は止まりません。** 拒否、検証落ち、API の失敗は定型文で公開し、`status.json` の `ai` に件数を記録します。認証の失敗はデータを保存した上で終了コード 2 にします。
- **費用には上限があります。** 1回の実行で $1.5、200件までです。本文が変わった項目だけ作り直します。プロンプトを変えても既存の要約は作り直さないので、作り直すときは `summaries.json` の該当項目を消します。情報源から消えて本文を読めない項目は、要約待ちから外します。

検証は機械的なものなので、製品の取り違えや書かれていない推測は検出できません。要約には AI 生成と分かる表示と公式へのリンクを付けます。

### 要約の手動差し替え

`src/pipeline/summary/overrides.json` に項目の `id` を指定します。`summary` を `null` にすると要約を出さず、定型文で公開します。

```json
{
  "0123456789abcdef": { "summary": "修正後の要約", "reason": "修正の理由" }
}
```
